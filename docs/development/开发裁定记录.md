# 开发裁定记录

以下22项按计划ledger的裁定顺序整理，保留判断依据及判断有误的代价；不改变原用户提示词，也不是完成证明。后续裁定将在最终交付前追加核准。

1. 在用户指定的新目录和独立分支开发，复用该目录作为隔离，不额外建 worktree。依据是明确路径要求；判断有误的代价是调整分支位置，原参考项目保持只读。
2. 本机使用独立 PostgreSQL 17，保留部署用 PostgreSQL 18 配置。避免控制现有服务；代价是目标 PG18 环境仍需验证。
3. 按已批准的完整方案与 code-first 连续执行，不重复索取方法或继续许可。代价限于可审阅、可撤回的本地代码变更。
4. 基础任务先定义实际使用的基础实体，各领域任务再添加强类型模型及迁移。避免猜字段；代价是跨任务协调迁移。
5. HTTP 数据库依赖拥有唯一事务，成功响应前提交，业务方法不自行提交或嵌套事务。代价是后续接口必须遵守该契约，否则须修正事务边界。
6. 财务任务先建立真实需要的单位和仓库主档，物流任务再扩展字段。代价是后续经审查的模型迁移。
7. 增补独立的完整110自然语言交互任务，不能把结构化动作API称为完整集成。代价是额外适配代码和测试，外部通道仍不自动启用。
8. 相同图片的新内容按完整交易依据审核：纯消息ID/时间戳变化不等于实质变化，新增实质内容须当前授权评估。疑义冻结核验依据，保留现金、占用和历史事实。代价是补证需额外人工审核，不能靠关键词或图片哈希自动定性。
9. 只启动明确核实归本项目所有且已停止的PG17数据目录。代价是本地实例恢复工作；不控制系统服务、旧项目或网络。
10. 计费到货、目的仓确认、清关和实际提货分开。使用已有节点及冻结的批次覆盖关系，旧仓库确认不自动覆盖未来到货。代价是增加明确确认与回归测试，不新增收费政策。
11. 缺少可信仓库归属时，使用强类型来源实体及受控原生桥接；原数据仍在正常业务视图显示。代价是增加解析/归属确认和投影工作，不能用假仓库或现金填空。
12. 活跃SQLite WAL不能仅凭只读连接或前后哈希稳定保证源文件不变。要求来源方一致性导出，或明确冻结的完整DB/WAL包；只在自有副本上备份和校验。代价是未来正式源采集仍需来源方提供一致性条件。
13. 海运原始KG缺失且有明确非KG计费依据时允许未知KG，已知KG及件数/体积约束保留。未知不按已知子集推造总重。代价是可空类型及跨领域回归，不改变计费政策。
14. 用独立强类型旧账银行证据关联补充历史核验，不生成新付款或核销。银行占用、当前版本、金额覆盖、来源和权限仍校验。代价是新关联模型与状态的全链回归，不能把历史人工实收变成新现金。
15. 应付期间必须由实际来源或当前授权确认提供；完整组账应有可执行的变更、整组作废与恢复。代价是显式补充期间及组账审核步骤，缺依据的历史余额仍待核对。
16. 用 LegacyBillApplication 和 LegacyGroupRevision 分开保存不可变原账与当前应用，整组调整只作用一次。作废冻结旧应用，恢复不自动重新分配新现金；允许版本化解析修复。代价是增加强类型模型、预览和版本勾稽。
17. 已有资金的客户归属更改走明确归属核对：旧资金冻结在原归属，真实原生核销只退回原付款人，新归属欠款依据明确。代价是额外的归属证据与权限；不推造付款人、币种或资金转移。
18. 恢复冻结期间只允许签名有效的原边界回执事实入库，不执行消息、采集、财务、恢复或发送动作。代价是窄回执例外的专门验证；避免丢弃已发生的外部结果或错误重发。
19. 应收上传日期需真实上传来源或明确输入，不把原账日期/今天替代；应付原账日期可表示会计/账单日，期间另行确认。代价是缺失日期的人工补充和明确字段语义。
20. 旧银行同额身份有歧义时保留原始行及历史占用，受控争议状态或逐行确认后才可继续；不能因歧义回滚掉全部历史，也不能释放原占用。代价是增加身份裁定步骤，未证明的双占用继续冻结。
21. 付款冲正请求释放银行占用也必须经过身份歧义保护。代价是冲正时额外核对；实际付款、分配、提货及投递事实保留，已入账款不能变成可再次入账。

22. 目的仓提货照片使用专用上传与读取，绑定当前指令、成员及目的仓；历史实提原图在剩余量为零后仍可按事实目的仓授权读取。代价是增加专用端点和当前权限/版本/文件校验回归，不能扩大成全局附件、来源仓或财务/银行权限。
