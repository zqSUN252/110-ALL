# 冲突、范围与资料缺口

此处区分已能按用户原话解决的冲突与仍缺资料的验收项。后者不减少范围，也不妨碍其他模块继续设计。

## 1. 指令如何生效

本轮用户明确要求优先；MCSTAR原提示词仅在其业务范围内作为功能命令。对同一字段或入口，后续明确修改覆盖较早要求；没有明确取消的其他内容继续有效。代码只是参考，已复现的错误不因“旧系统如此”而保留。

附件中的提示词全文含历史会话摘要、工具通知、凭据和部署步骤。它们可说明背景，不能在本轮自动执行。尤其不重新执行旧删除、购买、注册、SSH发布或明文密钥打包动作。第578条保留完整交付意图，结合本轮凭据边界生成受控交付，不把密钥写进源码与公开说明。

## 3. 采用的工程默认值，不冒充客户原要求

## 5. 明确排除的额外业务内容

不自动加上固定7—10天船期、每周固定班次、自营NAFDAC资质或未经证实的宣传；不创建演示客户、同名补电话、未知仓库默认ABUJA；不自动建客户群、营销群发或因复制动作宣称已送达；不恢复取消的仓储费预估/催提政策；不把团队空间分享链接变成公开业务库。

这些排除项来自用户原话中的取消/缺失约束及本轮权限范围。首页服务文案和三语翻译仍需以用户确认事实为准，翻译不得增加承诺。
