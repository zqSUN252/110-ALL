## 已确定的方案

1. 以110的 FastAPI / React 基础重建模块化统一系统，使用 PostgreSQL 保存统一业务事实；110原有SQLite访问须逐模块适配。
2. 以用户提示词约束MCSTAR业务，保留完整范围；不直接运行旧的整表覆盖同步、匿名数据下载及固定口令恢复逻辑。
3. 银行到账、付款证据、账单核销、放货指令、目的港实际放货各有独立状态。银行一笔入账对应一笔付款，付款可分配多张账单。
4. 回填先核对正式来源，保留原始行、附件和审核证据；不将QA库、历史测试账或旧快照混进现有应收。

## 当前资料边界

包内最新快照含28份出运单、964行票件、619张账单、60条水单和73条付款台账记录。964行中有917个非空收据号；同号多行可能是合法明细或分批，不能据此去重。单位引用有12个非空失配及1条空引用，42个非空运单引用失配，均保留异常而不补造关联。

尚未取得MCSTAR和110当前生产的一致性备份；包内最新快照缺入库台账、MBL、客户注册等业务键，也缺首页两张宣传原图。当前方案明确保留这些功能，待取得真实资料后完成回填及相应验收。
